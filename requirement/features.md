# 功能要点

> 规则与公式见 [README.md](README.md)，交互流程见 [journeys.md](journeys.md)，命名与字段契约见 [conventions.md](conventions.md)。

## 1. 功能清单（四方案共同底线）

| ID | 功能 | 说明 | 验收要点 |
|---|---|---|---|
| F1 | 记录到岗 | 选择工作日（今天及以前）标记为到岗 | 记录成功；A +1；统计即时更新 |
| F2 | 记录请假 | 选择工作日（今天及以前，或当前月未来工作日）标记为请假 | 记录成功；L +1；W −1；need 重算 |
| F3 | 修改/取消 | 今天及以前可到岗/请假/清除；当前月未来工作日只能请假/清除 | 同一天只有一条记录；统计即时更新 |
| F4 | 本月统计 | A、W、R、need、remain、状态 | 与 README 验收用例一致 |
| F5 | 剩余可用工作日 | S = 今天到月末的工作日数（含今天、含调休补班日）− 未来请假日数；是否来得及 | 仅当前月；含今天；扣未来请假 |
| F6 | 历史月份 | 查看统计与到岗/请假日期明细；可修改 | 不展示 S 与「是否来得及」 |
| F7 | 公休假与调休数据 | 读取预置 JSON；周末由程序计算 | 调休补班日计为工作日、可标记 |
| F8 | 持久化 | 重启/重新打开后数据不丢 | 本地或服务端按方案实现 |
| F9 | 单用户 | 无账号、无他人数据 | 聊天/文档方案按各自形态限制 |

## 3. 交互要求

- 手机优先，单手可完成核心操作。
- 首屏可见核心数字：已到岗、还需几天、是否合格。
- 核心操作不超过 2 步。
- 不可操作时给出原因，不只置灰。
- 四个方案使用一致的统计文案和日期明细格式。
- 写操作完成后立即刷新统计，不要求用户再次查询。

## 4. 非目标

- 多人使用、查看他人、排名/社交。
- 请假审批流、与公司考勤系统对接。
- 提醒/推送、Android 桌面小组件。
- 数据导出、跨方案同步。
- 桌面端交互。
- 半天假、按小时统计。
- 历史趋势图、复杂报表。

## 5. 验收方式

- 每个方案至少覆盖 [README.md](README.md) 第 7 节的 11 个用例与 S 用例。
- 同一天重复标记、未来请假、未来到岗、非工作日、`W = 0`、失效记录需单独验证。
- 四方案对同一组输入应输出相同的 A、W、R、need、remain、状态。
