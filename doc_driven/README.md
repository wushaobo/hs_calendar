# 到岗会疯 · doc_driven

用手机 AI app + 预置文档 + 一个通用 skill 追踪个人到岗率：
`当月到岗天数 ÷ 当月工作日天数 ≥ 30%`。
不写服务端、不做专用 App、不做机器人；数据是本地 CSV，规则是本地 Markdown。

## 1. 文件清单

| 文件 | 作用 | 是否可改 |
|---|---|---|
| `records.csv` | 到岗/请假记录，唯一数据源，一天一行 | 可通过 skill 增删改，也可手工编辑 |
| `holidays.json` | 公休假与调休补班配置 | 只读；更新时整体替换 |
| `rules.md` | 业务规则、公式、字段、算例，唯一口径 | 不应修改 |
| `skill.md` | 通用系统提示：短指令、流程、回复模板、错误处理 | 不应修改 |
| `README.md` | 本文件：加载、使用、备份、更新、限制 | — |
| `verification.md` | 12 条黄金用例与流程用例的验证记录 | — |

## 3. 加载到手机 AI app

任选一种通用方式，不需要特定 app 的功能：

1. **项目/知识库**：新建一个项目或知识库，上传 `rules.md`、`skill.md`、
   `records.csv`、`holidays.json`，把 `skill.md` 设为固定指令或系统提示。
2. **会话附件**：新开一个会话，把四个文件作为附件发送，并把 `skill.md` 的内容
   粘贴为首条固定指令。
3. **直接粘贴**：文件不大时，把 `skill.md` 与 `rules.md` 粘贴到系统提示/自定义指令，
   把 `records.csv` 与 `holidays.json` 作为附件或代码块提供。

加载后先发一条「本月」，应看到类似回复：

```text
2026 年 11 月
已到岗 0 天 / 工作日 21 天
占比 0.0%，还需 7 天
剩余 11 个工作日，来得及

到岗：无
请假：无
```

确认两件事：

- 回复中的「今天」与手机日期一致；不一致时先告诉 skill「今天是 YYYY-MM-DD」。
- 当前 app 是否允许修改挂载的 `records.csv`。不允许时，skill 会输出变更行和完整
  CSV，由你手工替换，并明确标注「未保存」。

## 4. 日常使用

| 想做什么 | 发什么 |
|---|---|
| 查看本月 | `本月` / `还差几天` |
| 今天到岗 | `到岗` / `今天到岗` |
| 今天请假 | `请假` / `今天请假` |
| 补记某天 | `11/12到岗` / `11月12日请假` |
| 改状态 | `11/12改成请假` |
| 取消某天 | `取消11/10` / `撤销11月10日` |
| 查历史月 | `10月` / `2026-10` / `看下10月` |
| 帮助 | `帮助` |

规则要点：

- 只能记录工作日（含调休补班日）中今天及以前的日期。
- 未来日期、周末、公休假会被拒绝，并说明原因。
- 同一天重复标记直接覆盖，不需要先取消。
- 历史月可查看也可修改；历史月不展示「是否来得及」。
- 未来月只显示该月工作日数，不展示到岗统计。

## 5. 备份与恢复

`records.csv` 是唯一记录来源，备份它就是备份全部数据。

- **备份**：定期把 `records.csv` 复制到手机其他目录或自己的存储空间，
  文件名可带日期，如 `records-2026-11-14.csv`。
- **恢复**：用备份文件整体替换当前的 `records.csv`，保留表头
  `date,status,updatedAt`，然后重新发「本月」确认。
- **手工编辑**：可以，但必须保持三列、日期 `YYYY-MM-DD`、状态
  `on_site`/`leave`、同日期只有一行；编辑后让 skill 重新读取。
- 不做云同步；换手机时手工复制两个数据文件即可。

## 6. 更新节假日

1. 取得新版本的 `holidays.json`，确认顶层字段完整：
   `schemaVersion`、`dataVersion`、`updatedAt`、`timezone`、
   `holidays`、`workdayOverrides`。
2. 整体替换本目录的 `holidays.json`，不要只改其中几行。
3. 把新 `dataVersion` 记录到本 README 第 2 节。
4. 让 skill 重新读取后查一次本月，确认工作日数与预期一致。
5. 若配置变化导致已有记录所在日期不再是工作日，skill 会把它列为「失效记录」，
   按提示清除或修正；数据不会被自动删除。

当前只有 2026 年数据。查询 2027 年月份时，skill 按周末规则计算并提示数据未配置；
记录 2027 年日期会被拒绝，直到补入对应年份数据。

## 7. 测试

12 条黄金用例（来自共享规格）、6 条流程用例和逐项核对结果见
[`verification.md`](verification.md)。测试为手动/模拟执行：把用例数据临时写入
`records.csv`，在 AI 会话中发对应指令，逐项核对统计、状态文案和 CSV 变更，
完成后恢复空表。

核心核对点：

- 2026-11 的 `W0 = 21`，`need = 7`；`S` 从今天（含）算到月末。
- 2026-02 的 `W0 = 16`（20 个工作日 − 6 个公休 + 2 个调休补班）。
- 2026-10 的 `W0 = 19`。
- 半向上舍入：`5/16 = 31.25% → 31.3%`，`4/19 = 21.05% → 21.1%`。
- 整月请假 `W = 0` 显示「本月无需到岗」，不出现除零。
- 周六记录进入 `invalid_records`，不计入到岗天数。

## 8. 已知限制

- 不同 AI app 的文件读写能力不同。不能写文件时，需要手工替换 CSV；skill 会明确
  标注「未保存」，不会假装写入。
- 日期解析支持常见写法，但不支持「上周五」「周三」这类相对星期。
- 无状态词的裸日期会追问「到岗还是请假」，不会自动猜测。
- 2027 年节假日数据待补，跨年查询结果可能不准。
- 不做提醒、推送、导出、云同步、多人共享。
- 没有日历视图，只有文字统计与 CSV 明细。
- 规则变更需要更新 `rules.md` 并在独立需求 session 中递增 specVersion。

## 9. 故障排查

| 现象 | 处理 |
|---|---|
| 提示缺少文件 | 确认四个文件都在当前项目/会话中，文件名与大小写一致 |
| 提示 `records.csv` 表头错误 | 第一行改为 `date,status,updatedAt` |
| 提示第 N 行格式错误 | 检查该行列数、日期格式、状态拼写 |
| 日期被拒 | 确认是工作日、今天及以前；调休补班日可以记录 |
| 统计与预期不符 | 核对 `holidays.json` 的 `dataVersion` 和当天日期 |
| 提示「未保存」 | 当前 app 不能写文件；按输出替换 `records.csv` 后回复「已替换」 |
| 提示 2027 数据未配置 | 查询可继续但结果不确定；写入需先补节假日数据 |
