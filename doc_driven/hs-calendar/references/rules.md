# 到岗会疯 · 业务规则（doc_driven）

> 本文件是 doc_driven 方案唯一的业务口径来源。`SKILL.md` 只负责流程与文案渲染，
> 不得自行改写这里的公式、状态码或文案。
> 本文件不依赖任何仓库路径；全部数据来源是 skill 包内的 `holidays.json` 与
> 资料库中的 `records.csv`。

## 1. 定位与版本

- 用途：单用户按自然月追踪个人到岗率，判定条件为
  `当月到岗天数 ÷ 当月工作日天数 ≥ 30%`。
- 运行环境：手机 AI app 的 skill 包 + 资料库；读取 skill 包内的 `rules.md`、
  `SKILL.md`、`holidays.json` 与资料库中的 `records.csv` 后工作；不使用本项目
  自建的服务端，数据不做跨设备同步。
- 版本常量：

| 项 | 值 |
|---|---|
| specVersion | `2` |
| holiday dataVersion | `2026.1` |
| 时区 | `Asia/Shanghai` |
| 阈值 | `0.30`（固定，无设置入口） |

若 `holidays.json` 的 `dataVersion` 与上表不一致，以 JSON 为准，并提示用户
skill 包的节假日版本与规则记录不一致。

## 2. 术语与状态码

### 2.1 术语

| 术语 | 定义 |
|---|---|
| 到岗 | 当天到公司上班，一天一条记录 |
| 请假 | 当天请假，一天一条记录；与到岗互斥 |
| 公休假 | 法定节假日、公司额外假期等非工作日，由 `holidays.json` 的 `holidays` 预置 |
| 周末 | 周六、周日 |
| 调休补班日 | 官方安排周末上班的日期；计为工作日，可记录，由 `workdayOverrides` 预置 |
| 工作日 | `(周一至周五 − 公休假) ∪ 调休补班日` |
| 可标记日期 | 今天及以前的工作日可到岗/请假；当前月未来工作日仅可请假 |
| 今天 | 按 `Asia/Shanghai` 计算的当前日历日 |

### 2.2 记录状态

只有两种，写入时不得出现其他值：

| 状态码 | 含义 |
|---|---|
| `on_site` | 到岗 |
| `leave` | 请假 |

### 2.3 结果状态与文案

判定顺序固定为：`data_error` → `no_need` → `qualified` →
历史月 `below_target_ended` → 当前月 `too_late` → 当前月 `needs_days`。

| 状态码 | 条件 | 文案 |
|---|---|---|
| `data_error` | `L > W0` | 数据异常，请检查请假记录 |
| `no_need` | `W = 0` | 本月无需到岗 |
| `qualified` | `remain = 0` | 已合格（`A > need` 时可附「超出 A − need 天」） |
| `below_target_ended` | 历史月且 `remain > 0` | 未达标（本月已结束） |
| `too_late` | 当前月且 `S < remain` | 已来不及 |
| `needs_days` | 当前月且 `S ≥ remain` 且 `remain > 0` | 还差 {remain} 天 |

未来月份不属于以上任何一种：只展示工作日数量，不计算到岗统计。

## 3. 工作日集合与 W0

### 3.1 集合公式

```text
workdaySet(month) = { d ∈ month |
  (d 是周一至周五 且 d ∉ holidays) 或 d ∈ workdayOverrides
}
W0 = |workdaySet(month)|
```

- 调休补班日即使落在周六/周日，也属于工作日，可标记到岗/请假。
- `holidays` 可以包含落在周末的公休假日期；周末本来就不计工作日，统计上无额外影响。
- 未列出的日期按「周一至周五为工作日、周六周日为休息日」计算。
- 同一日期不得同时出现在 `holidays` 与 `workdayOverrides`；冲突视为配置错误，停止计算。

### 3.2 星期推算

日期与星期一律按公历计算，不做时区换算。为便于无代码环境人工核对，
2026 年各月 1 日星期与未扣节假日的周一至周五天数如下：

| 月份 | 1 日星期 | 周一至周五天数 | 扣除公休假并加调休后的 W0 |
|---|---|---|---|
| 2026-01 | 四 | 22 | 21（元旦 1/1） |
| 2026-02 | 日 | 20 | 16（春节 −6，调休 +2） |
| 2026-03 | 日 | 22 | 22 |
| 2026-04 | 三 | 22 | 21（清明 4/5 为周日、4/6 为周一） |
| 2026-05 | 五 | 21 | 19（劳动节 5/1、5/4 为周一至周五） |
| 2026-06 | 一 | 22 | 21（端午 6/19） |
| 2026-07 | 三 | 23 | 23 |
| 2026-08 | 六 | 21 | 21 |
| 2026-09 | 二 | 22 | 21（中秋 9/25） |
| 2026-10 | 四 | 22 | 19（国庆 10/1、10/2、10/5 为周一至周五） |
| 2026-11 | 日 | 21 | 21 |
| 2026-12 | 二 | 23 | 23 |

权威计算始终以 `holidays.json` 的实际内容为准，上表只用于人工核对。

### 3.3 数据未覆盖的年份

`holidays.json` 当前只覆盖 2026 年（dataVersion `2026.1`），2027 年待补。

- 查询未覆盖年份：按「周一至周五为工作日、周六周日为休息日」计算，
  并在回复末尾提示：`{year} 年节假日数据未配置，仅按周末规则计算`。
- 写入未覆盖年份：拒绝，文案 `{year} 年节假日数据未配置，暂不可记录`。
- 不猜测未公布节假日，不自动生成配置。

## 4. 有效记录与失效记录

### 4.1 有效记录

一条记录满足以下条件，才是有效记录：

1. 日期属于当月的 `workdaySet`；
2. 状态为 `on_site` 或 `leave`；
3. 若日期 `> today`，只有 `leave` 有效，`on_site` 无效；若日期 `≤ today`，
   两种状态均有效。

只有有效记录计入 `A`、`L`、`W`。当前月未来的有效请假也计入 `L`，并从 `S` 中扣除。

### 4.2 失效记录

不满足上述条件的记录进入 `invalid_records`，元素为 `{date, status}`。
失效记录：

- 不计入 `A`、`L`、`W`；
- 不自动删除、不自动修改；
- 查询时追加提示 `失效记录：{日期}（{状态}），建议清除`。

典型来源：公休假/调休配置变更后日期不再是工作日；历史数据中误写了周六、
未来到岗、未来非工作日请假或非法状态。

### 4.3 写入拒绝与读取标记的区别

- 用户新写入时：不满足条件的日期直接拒绝，不进入 `records.csv`。
  - 当前月未来工作日只能写 `leave`，不能写 `on_site`；未来月份只读。
  - 未来工作日写 `on_site` 用「未来工作日只能标记请假，不能标记到岗」；
    未来月份用「未来月份只读」；周末/公休假用「非工作日不可记录」。
- 读取已有数据时：不满足条件的记录按 4.2 标记为失效记录，不清除。
- 删除操作（未到岗/取消/清除/撤销）只删除该日期的记录，不要求工作日或未来日期；
  记录不存在时不做修改。
- 若某日期因调休配置变化重新变成工作日，允许补录。

## 5. 月度指标

### 5.1 变量

| 变量 | 定义 |
|---|---|
| `W0` | 当月工作日集合的日期数 |
| `L` | 当月有效请假天数 |
| `A` | 当月有效到岗天数 |
| `W` | `max(0, W0 − L)` |
| `need` | 达标所需到岗天数 `ceil(0.3 × W)` |
| `remain` | 还差天数 `max(0, need − A)` |
| `R` | 到岗率 `A / W` |
| `S` | 今天（含）到月末的工作日数 − 未来请假日数，含调休补班日；仅当前月计算 |
| `feasible` | `S ≥ remain`；仅当前月且 `W > 0` |

### 5.2 公式与整数实现

```text
W = max(0, W0 − L)
need = (3 × W + 9) // 10            # 等价于 ceil(0.3 × W)，// 为向下取整
remain = max(0, need − A)
rate_percent = round_half_up(A / W × 100, 1)
S = count(d ∈ workdaySet(month) 且 today ≤ d ≤ monthEnd)
  − count(有效 leave 记录且 date > today)
feasible = (S ≥ remain)
```

- `rate_percent` 四舍五入保留 1 位小数，0.5 向上。
- 避免浮点误差的整数实现：
  `rate_percent = floor((2 × A × 1000 + W) / (2 × W)) / 10`。
- `W = 0` 时 `rate_percent = null`，不得除零。
- `S` 包含今天，且不因今天已有到岗/请假记录而扣减；但会扣除未来请假日。
- 未来请假 = 日期 `> today` 且状态为 `leave` 的有效记录；未来到岗无效，不参与计算。
- 分母始终是整月工作日，不按「截至今天」截断。
- `need` 速查：

| W | 10 | 16 | 18 | 19 | 20 | 21 |
|---|---|---|---|---|---|---|
| need | 3 | 5 | 6 | 6 | 6 | 7 |

### 5.3 字段空值规则

| 字段 | 类型 | 空值规则 |
|---|---|---|
| `w0` | integer | 非空 |
| `leave_days` | integer | 非空 |
| `working_days` | integer | 非空；`data_error` 时为 0 |
| `on_site_days` | integer | 非空 |
| `need` | integer \| null | `data_error` 时为 `null`；`no_need` 时为 0 |
| `remain` | integer \| null | `data_error` 时为 `null`；`no_need` 时为 0 |
| `rate_percent` | number \| null | `W = 0` 或 `data_error` 时为 `null` |
| `remaining_workdays` | integer \| null | 非当前月、`W = 0` 或 `data_error` 时为 `null` |
| `feasible` | boolean \| null | 非当前月、`W = 0` 或 `data_error` 时为 `null` |
| `result_status` | string | 非空 |
| `invalid_records` | array | 元素 `{date, status}`，可为空数组 |

## 6. 结果判定

按以下顺序执行，命中即停止：

```text
1. L > W0                  → data_error
2. W = 0                   → no_need
3. remain = 0              → qualified
4. 历史月 且 remain > 0    → below_target_ended
5. 当前月 且 S < remain    → too_late
6. 当前月 且 S ≥ remain    → needs_days
```

月份类型：

| 类型 | 条件 | 行为 |
|---|---|---|
| 历史月 | 月份 < 当前月 | 正常统计；不展示 `S` 与「是否来得及」 |
| 当前月 | 月份 = 当前月 | 正常统计；展示 `S` 与是否来得及 |
| 未来月 | 月份 > 当前月 | 不计算到岗统计，只展示该月工作日数 `W0` |

`data_error` 时不输出 `need`、`remain`、`rate_percent`、`S`，只提示数据异常。
`no_need` 时不输出 `rate_percent` 与 `S`。

## 7. 日期与展示

- 存储格式：`YYYY-MM-DD`，不做时区换算。
- 明细展示：不补零的 `M/D`，如 `11/2`、`9/5`。
- 跨年展示：明细日期年份不等于今天所在年份时，补全年份为 `YYYY/M/D`，
  如 `2025/12/31`。
- 月份标题：`YYYY 年 M 月`，如 `2026 年 11 月`。
- 日期比较：`YYYY-MM-DD` 字符串可直接按字典序比较。
- 一周从周日开始只影响日历列顺序；工作日仍为周一至周五（本方案无日历视图）。

## 8. 数据文件契约

### 8.1 records.csv

唯一记录来源，位于 AI app 的资料库，不在 skill 包内。聊天内容不是数据源。

```csv
date,status,updated_at
```

| 项 | 规定 |
|---|---|
| 编码/换行 | UTF-8 无 BOM，LF |
| 列顺序 | 固定 `date,status,updated_at`，不得增删列 |
| `date` | `YYYY-MM-DD`，主键 |
| `status` | 仅 `on_site` 或 `leave` |
| `updated_at` | ISO-8601 带东八区偏移，如 `2026-11-14T21:30:00+08:00` |
| 空表 | 仅表头一行 |
| 唯一性 | 同一日期只保留一行 |
| 覆盖 | 同日期再次写入时直接替换，无需先删除 |
| 排序 | 写入后按 `date` 升序排列；读取时不要求已排序 |
| 读取容错 | 允许行尾空格；缺列、非法日期、非法状态的行按格式错误报告 |

写入必须通过 app 的资料库文件工具全量重写：保留表头，删除同一日期的旧行，
加入新行，按日期排序，再整文件替换资料库中的 `records.csv`。写入后必须回读，
确认目标行存在且状态正确。

批量写入时：

- 所有操作合并为一次全量重写，不得逐项 replace。
- 按消息顺序应用；同一日期出现多次时后写覆盖前值，最终每个日期只保留一行。
- 部分执行：只写入通过校验的项，失败项不写入。
- 写入后逐项回读确认成功项，并确认失败项未被写入。

### 8.2 holidays.json

只读配置，位于 skill 包 `data/`，不得由 skill 修改。

| 字段 | 必填 | 说明 |
|---|---|---|
| `schemaVersion` | 是 | 当前 `1` |
| `dataVersion` | 是 | 当前 `2026.1` |
| `updatedAt` | 是 | 数据最后更新日期 `YYYY-MM-DD` |
| `timezone` | 是 | 固定 `Asia/Shanghai` |
| `holidays` | 是 | 公休假数组，元素 `{date, name}`，`date` 唯一 |
| `workdayOverrides` | 是 | 调休补班日数组，元素 `{date, name}`，`date` 唯一 |

- `name` 可缺省，缺省视为空字符串。
- 未知字段忽略，保证向前兼容。
- 两个数组的日期不得重复。
- 文件缺失、JSON 非法或配置冲突时停止计算，并按 `SKILL.md` 的错误表回复。
- `updatedAt` 是 `holidays.json` 自身的元数据字段，与 `records.csv` 的
  `updated_at` 不是同一个字段。

## 9. 回复结构

### 9.1 当前月（`needs_days`）

```text
2026 年 11 月
已到岗 4 天 / 工作日 19 天（已请 2 天假）
占比 21.1%，还需 2 天
剩余 11 个工作日，来得及

到岗：11/2、11/3、11/5、11/6
请假：11/9、11/10
```

- 第 2 行的「（已请 L 天假）」只在 `L > 0` 时出现。
- 第 4 行只在当前月且 `W > 0` 时出现。

### 9.2 各状态的第 3、4 行

| 状态 | 第 3 行 | 第 4 行 |
|---|---|---|
| `needs_days` | `占比 {R}%，还需 {remain} 天` | `剩余 {S} 个工作日，来得及` |
| `qualified` | `占比 {R}%，已合格`；`A > need` 时写作 `占比 {R}%，已合格（超出 {A−need} 天）` | `剩余 {S} 个工作日` |
| `too_late` | `占比 {R}%，还需 {remain} 天` | `剩余 {S} 个工作日，已来不及` |
| `no_need` | `本月无需到岗` | 不输出 |
| `data_error` | `数据异常，请检查请假记录` | 不输出 |
| 历史月且 `remain > 0` | `占比 {R}%，未达标（本月已结束）` | 不输出 |
| 历史月 `qualified` | `占比 {R}%，已合格` | 不输出 |

### 9.3 明细行

```text
到岗：11/2、11/3、11/5
请假：11/9、11/10
```

- 只列有效记录，按日期升序，用「、」分隔。
- 无记录时写 `到岗：无` / `请假：无`。
- 跨年时按第 7 节补年份。

### 9.4 未来月

```text
2026 年 12 月
该月尚未开始，暂不展示到岗统计。该月工作日 23 天。
```

### 9.5 失效记录提示

统计块之后另起一行：

```text
失效记录：11/14（on_site），建议清除
```

多条失效记录用「、」分隔；没有则不输出该行。

### 9.6 批量操作

逐项确认按消息顺序列出，随后附当前月统计块。统计块按 9.1–9.5 的当前月模板；
历史月/未来月只逐项确认，不另出统计。

全部成功：

```text
已处理 {N} 项：
已记录 11/11 到岗
已记录 11/13 到岗

<当前月统计块>
```

部分成功 / 有未处理或有变化：

```text
已处理 {N} 项，{U} 项未处理，{K} 项无变化：
已记录 11/27 请假（未来请假）
已记录 11/4 请假
未处理 11/28：非工作日不可记录
11/12 没有记录，未做修改

<当前月统计块>
```

无任何可执行变更：

```text
没有可执行的变更：
未处理 11/28：非工作日不可记录
11/12 没有记录，未做修改

<当前月统计块>
```

写入失败：

```text
写入失败，整批未保存：
11/11 到岗
11/13 到岗
```

规则：

- 汇总行只列出非零计数：`已处理 {N} 项`；有未处理加 `，{U} 项未处理`；
  有无变化加 `，{K} 项无变化`。
- 逐项确认格式：新增/覆盖 `已记录 {M/D} {到岗|请假}`，覆盖时加
  `（覆盖原记录：{原状态}）`；删除 `已取消 {M/D} 记录（原为{原状态}）`；
  删除无记录 `{M/D} 没有记录，未做修改`。
- 未来请假可写 `（未来请假）`。
- 未处理项格式：`未处理 {M/D}：{原因}`；原因复用 `SKILL.md` 第 12 节固定文案。
- 跨月变更：逐项确认后加一行 `另修改了其他月份：YYYY-MM，请单独查询`。
- 写入失败不出统计；回读部分不一致用 `写入未确认，记录可能未保存` 并列出未确认项。

## 10. 算例

以下算例的「今天」均指对应 `today`，用于逐字核对回复。

### 10.1 2026-11 无记录，today = 2026-11-16

- `W0 = 21`，`L = 0`，`A = 0`，`W = 21`。
- `need = (63 + 9) // 10 = 7`，`remain = 7`，`R = 0.0%`。
- `S = 11`（11/16–20、11/23–27、11/30），`feasible = true`。
- 状态 `needs_days`。

```text
2026 年 11 月
已到岗 0 天 / 工作日 21 天
占比 0.0%，还需 7 天
剩余 11 个工作日，来得及

到岗：无
请假：无
```

### 10.2 2026-11 请 1 天假、到岗 5 天，today = 2026-11-16

- 到岗 11/2–11/6，请假 11/9。
- `W0 = 21`，`L = 1`，`A = 5`，`W = 20`。
- `need = (60 + 9) // 10 = 6`，`remain = 1`，`R = 5 / 20 = 25.0%`。
- `S = 11`，`feasible = true`，状态 `needs_days`。

```text
2026 年 11 月
已到岗 5 天 / 工作日 20 天（已请 1 天假）
```
